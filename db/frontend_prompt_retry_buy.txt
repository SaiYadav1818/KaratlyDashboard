# Prompt for Frontend Team — Level 2 Retry Buy

## IMPORTANT
When Level 2 admin clicks "Retry Buy", the frontend calls ONLY ONE dashboard API:

```
POST http://localhost:8082/api/v1/admin/fulfillment/{request_id}/retry-buy
```

You do NOT call uatbckend.karatly.net directly.
You do NOT call Augmont directly.
You do NOT pass live rate / lockPrice / blockId / merchantId manually.

The backend automatically:
1. Fetches LIVE RATE from uatbckend.karatly.net
2. Picks lockPrice (gBuy for gold / sBuy for silver) + blockId from the live rate
3. Calls uatbckend buy/create with the correct wrapper format
4. Marks request PROCESSED (success) or REJECTED (failure)

## Request (Level 2 admin clicks Retry)
```
POST /api/v1/admin/fulfillment/1/retry-buy
Content-Type: application/json
```
```json
{
  "adminId": 7,
  "note": "Retrying buy with live rate"
}
```

## IMPORTANT for UI
- HTTP status is ALWAYS 200 — check the `success` field:
```js
if (data.success === true) {
    // show green badge PROCESSED
    // option: show live_rate_used to admin
} else {
    // show red badge REJECTED
    // show data.buy_response.message to admin
}
```

## UI flow on Level 2 dashboard
1. Level 2 sees pending request → click "Retry Buy"
2. Optional confirm modal (show amount + customer + note field)
3. Call the retry endpoint above
4. On success → refresh pending list → request no longer PENDING
5. On failure → show error from `buy_response.message`

## request_id source
`request_id` comes from:
- `POST /api/v1/admin/fulfillment/pending` → response `requests[].id`
- or `POST /api/v1/admin/fulfillment/create` → response `request_id`
