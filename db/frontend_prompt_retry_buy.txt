# Prompt for Frontend Team — Level 2 Retry Buy (Proxy)

## IMPORTANT — What to call
When Level 2 admin clicks "Retry Buy", frontend calls ONLY ONE dashboard API:

```
POST http://localhost:8082/api/v1/admin/fulfillment/retry-buy
Content-Type: application/json
```

You do **NOT** call uatbckend.karatly.net directly.
You do **NOT** call Augmont directly.

The dashboard API is a **pure proxy**: it forwards your body to
`https://uatbckend.karatly.net/api/v1/orders/buy/create` and returns the response.

---

## What you give in the request

You pass the full buy request (the exact format buy/create wants).

```json
{
  "merchantId": "KARATLY-CF-20260909102322182-71020400",
  "request": {
    "lockPrice": "15964.93",
    "metalType": "gold",
    "quantity": null,
    "amount": "103.00",
    "merchantTransactionId": "KARATLY-CF-20260909102322182-71020400",
    "uniqueId": "995875001313121985",
    "phoneNumber": "7989019142",
    "blockId": "Xeaa3EQX",
    "modeOfPayment": "CASHFREE",
    "mobileNumber": "7989019142"
  }
}
```

### Field source
| Field | Source |
|-------|--------|
| `merchantId` | `merchant_order_id` from pending request |
| `request.lockPrice` | live gold/silver buy rate (gBuy/sBuy) — frontend fetches from `/api/v1/rates/live` & picks gBuy/sBuy |
| `request.blockId` | live rate `blockId` |
| `request.metalType` | `gold` / `silver` |
| `request.quantity` | null (buy by amount) |
| `request.amount` | `order_amount` from pending request |
| `request.merchantTransactionId` | `merchant_order_id` from pending request |
| `request.uniqueId` | `customer_id` from pending request |
| `request.phoneNumber` / `mobileNumber` | `customer_mobile` from pending request |
| `request.modeOfPayment` | `CASHFREE` |

## Response — FAILURE
```json
{
  "status": "FAILED",
  "message": "400 Bad Request: Augmont request validation failed"
}
```
(or the error from uatbckend, e.g. `{"status":500,"error":"..."}`)

---

## How to detect success in UI
```js
const data = await response.json();
const ok = data && (data.status === "success" || data.payload?.statusCode === 200);
if (ok) {
    // show success: message (e.g. "Successfully bought 0.0062 grams")
} else {
    // show failure: message from data.message or data.error
}
```

---

## UI flow on Level 2 dashboard
1. Level 2 sees pending request → click "Retry Buy"
2. Frontend fetches live rate → fills `lockPrice` + `blockId` (or backend does it — choose ONE)
   - Option A (recommended, no extra call): backend fills live rate
   - Option B (frontend): call `POST /api/v1/rates/live` on uatbckend first, use `payload.result.data.rates.gBuy`/`sBuy` + `blockId`, then call retry-buy
3. Frontend builds body above from pending request + live rate
4. Call `POST /api/v1/admin/fulfillment/retry-buy`
5. Show success/failure from response

## Backend proxy definition (for reference)
```java
// Dashboard GoldFulfillmentController
@PostMapping("/retry-buy")
public Map<String, Object> retryBuy(@RequestBody Map<String, Object> body) {
    return service.retryBuy(body);   // forwards body to uatbckend buy/create
}
```
