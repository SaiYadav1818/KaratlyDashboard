# Frontend Integration Prompt — Gold Fulfillment with Retry (No Token)

## IMPORTANT: No JWT / Bearer Token needed
All fulfillment + dashboard endpoints below are **public**. You do NOT need an `Authorization` header.
Each request includes `adminId` directly in the request body.

Base URL: `http://localhost:8082`

## 5. Level 2: Retry Buy (uses LIVE RATE automatically)

```
POST /api/v1/admin/fulfillment/1/retry-buy
Body: { "adminId": 2, "note": "Retrying now" }
```

**What happens server-side:**
1. Dashboard fetches LIVE rate from sabbpegold (`POST /api/v1/rates/live`)
2. Extracts `lockPrice` and `blockId` for the metal type
3. Calls sabbpegold buy (`POST /api/v1/orders/buy/create`) with the SAME amount + merchantOrderId
4. Updates request status

**Response on success:**
```json
{
  "success": true,
  "request": {
    "id": 1,
    "sabbpe_order_id": "SABBPE_123",
    "status": "PROCESSED",
    "retry_count": 1,
    "last_retry_at": "2026-09-08 15:45:00"
  },
  "sabbpe_order_id": "SABBPE_123",
  "live_rate_used": "7150.50",
  "buy_response": {
    "status": "SUCCESS",
    "payload": { }
  }
}
```

**Response on failure:**
```json
{
  "success": false,
  "request": {
    "id": 1,
    "sabbpe_order_id": "SABBPE_123",
    "status": "REJECTED",
    "retry_count": 1,
    "last_retry_at": "2026-09-08 15:45:00"
  },
  "sabbpe_order_id": "SABBPE_123",
  "live_rate_used": "7150.50",
  "buy_response": {
    "status": "FAILED",
    "message": "Insufficient balance"
  }
}
```

---

## 6. Status Flow
```
PENDING  →  PROCESSED   (retry succeeded)
PENDING  →  REJECTED    (retry failed)
```

---

## UI Requirements

### Level 1 Dashboard
- Table of unfulfilled orders (from `/unfulfilled-cashfree`)
- "Send Request" button per row → opens modal with note → submit to `/fulfillment/create`
- After send, show success message with request_id

### Level 2 Dashboard
- Table of pending requests (from `/fulfillment/pending`)
- Each row: customer, order id, amount, metal type, note, status badge, retry count
- "Retry Buy" button → opens confirm modal showing:
  - Original amount
  - LIVE rate that will be used
  - Optional note
- On confirm → call `/fulfillment/{id}/retry-buy`
- Show result (success → PROCESSED badge, failure → REJECTED badge with error)

### Status Badge Colors
| Status    | Color   |
|-----------|---------|
| PENDING   | yellow  |
| PROCESSED | green   |
| REJECTED  | red     |

---

## Request Status Values
- `PENDING` — Level 1 sent, waiting for Level 2
- `PROCESSED` — gold bought via retry (success)
- `REJECTED` — retry failed
