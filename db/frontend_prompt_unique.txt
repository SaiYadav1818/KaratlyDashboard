# Frontend Integration — Fulfillment by Unique ID (No Token)

Base URL: `http://localhost:8082`
NO `Authorization` header needed. `adminId` is in the body.

## FLOW
```
Level 1 → sends ONLY uniqueId → Level 2 sees full details (merchant id, augmont msg) → retries with live rate
```

## 1. Lookup by Unique ID (Level 1 or Level 2)
Shows all order data + buy request details + Augmont message (from provider_response_payload)
```
POST /api/v1/admin/fulfillment/lookup-unique
Body: { "adminId": 1, "uniqueId": "09876543212" }
```
Response:

## 2. Create Request (Level 1) — ONLY uniqueId
```
POST /api/v1/admin/fulfillment/create
Body: { "adminId": 1, "uniqueId": "09876543212", "level1Note": "Gold not received" }
```
Response:
```json
{
  "success": true,
  "request_id": 1,
  "request": {
    "id": 1,
    "sabbpe_order_id": "SABBPE_123",
    "merchant_order_id": "MERCHANT_789",
    "customer_id": "09876543212",
    "order_amount": 5000.00,
    "metal_type": "gold",
    "status": "PENDING"
  },
  "message": "Request sent to Level 2 admin"
}
```

## 3. Pending Requests (Level 2)
```
POST /api/v1/admin/fulfillment/pending
Body: { "adminId": 2 }
```
Each request now includes:
- `merchant_order_id` (buy request id for Augmont)
- `augmont_message` (from provider_response_payload)
- `lock_price`, `block_id`, `metal_type`, `order_amount`, `retry_count`

## 4. Retry Buy (Level 2) — live rate
```
POST /api/v1/admin/fulfillment/1/retry-buy
Body: { "adminId": 2, "note": "Retrying" }
```
