# Frontend Prompt — Admin Password Flow

Base URL:
```text
http://localhost:8082
```

No bearer token is required.

## 1. Change Password

Use when the admin knows the existing password.

### Request
```http
POST /api/v1/admin/auth/change-password
Content-Type: application/json
```

```json
{
  "adminId": 7,
  "existingPassword": "oldPassword123",
  "newPassword": "newPassword456",
  "confirmPassword": "newPassword456"
}
```

### Success response
```json
{
  "success": true,
  "message": "Password changed successfully"
}
```

### Possible failure responses
```json
{
  "success": false,
  "message": "Existing password is incorrect"
}
```

```json
{
  "success": false,
  "message": "New password and confirmation do not match"
}
```

New passwords must contain at least 8 characters, one letter, and one digit.

## 2. Forgot Password

Use when the admin forgot the existing password. The identifier may be a phone number or email address.

### Request by phone
```http
POST /api/v1/admin/auth/forgot-password
Content-Type: application/json
```

```json
{
  "identifier": "8888888888"
}
```

### Request by email
```json
{
  "identifier": "level1@karatly.net"
}
```

### Success response
```json
{
  "success": true,
  "message": "Password generated successfully",
  "phoneNumber": "8888888888",
  "email": "level1@karatly.net",
  "generatedPassword": "A7kP92xLm4"
}
```

Display the generated password to the admin once. The backend stores only its BCrypt hash.

### Failure response
```json
{
  "success": false,
  "message": "Admin account not found or inactive"
}
```

## Frontend UI Flow

### Change Password screen
1. Show existing password field.
2. Show new password field.
3. Show confirm password field.
4. Validate new and confirm values match before submitting.
5. Call `/api/v1/admin/auth/change-password`.
6. Show success or the returned error message.

### Forgot Password screen
1. Show phone/email field.
2. Call `/api/v1/admin/auth/forgot-password`.
3. If `success` is true, display `generatedPassword`.
4. Tell the admin to use it for the next login.
5. The admin can later change it using the Change Password screen.

Always check the JSON `success` field; do not rely only on the HTTP status.
