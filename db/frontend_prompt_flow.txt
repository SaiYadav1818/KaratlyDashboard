# Karatly Dashboard — Gold Fulfillment Flow (Frontend Integration)

## Base URL
```
http://localhost:8082
```

## No Authentication / No Token
All endpoints below require **NO Authorization header**. Every request sends `adminId` (the id returned by login) directly in the JSON body.

---

## FLOW OVERVIEW

```
[LEVEL 1 ADMIN]                          [LEVEL 2 ADMIN (Super)]
Login                          →         Login
See unfulfilled orders                   See pending requests
Check details by uniqueId                Check details by uniqueId
Send request (only uniqueId)   →         Retry buy (uses LIVE RATE)
```

---

## STEP 0 — Login (for both levels)

### Request
```
POST /api/v1/admin/auth/login
Content-Type: application/json
```
```json
{
  "phoneNumber": "8888888888",
  "password": "admin@123"
}
```

### Response — SUCCESS
```json
{
  "success": true,
  "admin": {
    "id": 7,
    "phoneNumber": "8888888888",
    "fullName": "Level1 Admin",
    "email": "level1@karatly.net",
    "isSuperAdmin": false
  }
}
```
> Save `admin.id` (e.g. `7`) → use as `adminId` in every request.

### Response — WRONG credentials
```json
{
  "success": false,
  "message": "Invalid phone number or password"
}
```

## STEP 5 — [Level 2] Retry buy (uses LIVE RATE automatically)

### Request
```
POST /api/v1/admin/fulfillment/1/retry-buy
```
```json
{
  "adminId": 7,
  "note": "Retrying buy with live rate"
}
```
> `1` = the request_id from STEP 3.

### What backend does
1. Fetches live rate from sabbpegold → `https://uatbckend.karatly.net/api/v1/rates/live`
2. Extracts `lockPrice` (`rates.gBuy` for gold / `rates.sBuy` for silver) and `blockId`
3. Calls sabbpegold buy → `https://uatbckend.karatly.net/api/v1/orders/buy/create`
4. On success → marks request `PROCESSED` + updates `cashfreepg_orders.remarks='FULFILLMENT_COMPLETED'`
5. On failure → marks request `REJECTED`

### Response — SUCCESS
```json
{
  "success": true,
  "request": {
    "id": 1,
    "sabbpe_order_id": "Karatly2026090910232282c851",
    "customer_id": "995875001313121985",
    "order_amount": 103.00,
    "metal_type": "gold",
    "merchant_order_id": "KARATLY-CF-20260909102322182-71020400",
    "status": "PROCESSED",
    "level2_note": "Retrying buy with live rate",
    "retry_count": 1,
    "last_retry_at": "2026-09-09 11:07:18"
  },
  "sabbpe_order_id": "Karatly2026090910232282c851",
  "live_rate_used": "15940.49",
  "buy_response": {
    "status": "success",
    "payload": { "...Augmont buy result..." }
  }
}
```

### Response — FAILURE
```json

  "success": false,

    "id": 1,

  }
}
```

## STATUS FLOW

```
PENDING  →  PROCESSED   (retry gold buy succeeded)
PENDING  →  REJECTED    (retry gold buy failed)
```

| Status    | Meaning                          |
|-----------|----------------------------------|
| PENDING   | Level 1 sent, Level 2 must review |
| APPROVED  | (reserved)                        |
| PROCESSED | gold bought successfully          |
| REJECTED  | gold buy failed                   |

## UI REQUIREMENTS

### Level 1 Admin Dashboard
1. **Login form** → phone + password → show error if `success:false`
2. **Unfulfilled table** (STEP 1): columns → customer, mobile, amount, payment status, created date
3. Per row: **"Send Request"** button
   - optional note field
   - calls STEP 3 with `uniqueId = customer_id`
4. Show toast: `request_id` + confirmation

### Level 2 Admin Dashboard
1. **Login form** → same
2. **Pending table** (STEP 4): → customer, amount, metal, merchant_order_id, level1 note, retry count
3. Per row: **"Details"** (STEP 2 lookup) + **"Retry Buy"** button
4. **Retry** → confirm modal → calls STEP 5
5. Show result → success badge `PROCESSED` / failure message

### Status Badge Colors
| Status    | Color  |
|-----------|--------|
| PENDING   | yellow |
| PROCESSED | green  |
| REJECTED  | red    |

## SUCCESS RESPONSE CHECK
Always check `success` field (not HTTP status) — retry returns HTTP 200 even on buy failure:
```js
if (data.success === true) { /* ok */ } else { /* show data.message / data.buy_response.message */ }
```
